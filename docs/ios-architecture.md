# iOS Architecture

Open this when touching app flow, Swift source layout, recording, camera, persistence, or on-device session analysis.

## Project Layout

- `ios/Outbound/Outbound.xcodeproj`: main Xcode project.
- `ios/Outbound/Outbound`: iOS app source. Xcode uses file-system-synchronized groups, so new Swift files under this folder are picked up automatically.
- `ios/Outbound/SupportFiles/Info.plist`: app plist. `GENERATE_INFOPLIST_FILE = NO`, so required bundle keys and usage descriptions must stay here.
- `ios/Outbound/SupportFiles/OutboundDebug.entitlements`: empty Debug entitlements for personal-team device installs.
- `ios/Outbound/SupportFiles/Outbound.entitlements`: Release entitlements, including Sign in with Apple.
- `ios/Outbound/Outbound/GoogleService-Info.plist`: local Firebase config. This file is gitignored but is copied into the app when present.
- `Tests/OutboundSessionAnalysisTests`: Swift Package tests for the on-device session-analysis module.
- `Package.swift`: exposes only the session-analysis subset as `OutboundSessionAnalysis` for lightweight package testing outside the full iOS app target.

## App Entry

- `App/OutboundApp.swift`: app root. Calls `FirebaseBootstrap.configureIfAvailable()`, creates `AuthStore`, `GuideStore`, `GuideCatalogStore`, `ActivityStore`, `GoalStore`, `HealthAuthorizationStore`, `HealthImportStore`, and `DailyCheckInStore`, and shows `MainTabView` after Firebase authentication. When `OUTBOUND_ENABLE_SOCIAL` is defined, it also creates the Social-only local stores.
- `App/PlainstrideLinks.swift`: canonical `run.plainstride.com` invitation URLs and live-group Universal Link parsing. `OutboundApp` retains an incoming live-group invitation through authentication and joins it once the user is signed in.
- `App/AppDelegate.swift`: minimal UIKit bridge used by the SwiftUI app to hand Firebase Auth OAuth callback URLs back to `Auth.auth().canHandle(_:)` after hosted Google sign-in.
- `Core/PushNotificationCoordinator.swift`: notification authorization, APNs/FCM token synchronization, and pending Social notification routing. `AppDelegate` bridges Firebase Messaging and foreground/tap callbacks; see `docs/notifications.md` for the shared backend/client contract.
- `Core/Analytics/`: vendor-neutral async analytics protocol, thread-safe multi-provider manager, Firebase adapter, sanitization, and console-only fallback. `OutboundApp` injects the shared manager through `EnvironmentValues.analyticsManager`; feature types may also receive it through their initializer.
- `Core/AvatarImageCache.swift`: app-wide in-memory avatar image cache and request coalescer shared by Social, Me/profile, and generated activity share cards. Uploads seed the same cache so every visible surface can adopt the new image without a redundant download.
- `App/AuthStore.swift`: First-party Apple authentication wrapper using native `AuthenticationServices` and a nonce-verified backend exchange. Because Apple supplies the name only on first authorization, the client temporarily preserves that one-time name in the device-only Keychain until the backend session exchange succeeds. The backend returns the verified provider email as the login email; editable contact details remain separate profile data. Account deletion reauthorizes Apple, revokes the Apple token when possible, calls the backend deletion endpoint, erases local Outbound data, and signs out.
- `App/AuthView.swift`: login UI for Apple and Google provider sign-in only. Email/password and phone/password login are intentionally not user-facing.
- `App/MainTabView.swift`: coordinates the production shell with the retained `RecordView` session state and injects that recording instance into Today; it does not place an idle full-screen layer over the app shell. The canonical Today launch intent is shared with the Today card and prioritizes a customized workout, then an active calibration workout, then the current plan suggestion, so the displayed duration and live workout structure stay aligned. The retained idle instance is synchronously hidden whenever Today is not selected, preventing its setup overlays from appearing during native tab handoff. Countdown and live recording continue in the same retained instance so sessions can be hidden, recovered, and reopened without resetting.
- `App/FeedbackReporter.swift`: app-wide two-shake detector and lightweight Bug / Suggestion form. The shake shortcut is disabled while an activity is active or paused; Settings remains a discoverable alternative entry point. It captures the current screen and carries that image atomically into the presentation before showing the form, supports simple red-marker annotation with undo/removal, and submits the report plus current page and optional screenshot directly to the authenticated feedback API. Every delivered report identifies the authenticated user by ID and email. Optional diagnostics include app version, the specific device marketing model plus hardware identifier, and iOS version. Reports can also attach an opt-out, 15-minute, 200-line/30,000-character tail restricted to Plainstride-owned unified-log categories; private values remain redacted and token, email, and coordinate patterns receive a second scrub before upload. Submission results use temporary toast feedback. Analytics records the entry source, screen-capture result, submission result, and log-attachment state without including screenshot content, report text, logs, or page names.
- `Features/Simplified/SimplifiedAppShell.swift`: primary and only `Social · Today · Me` shell and owner of the native tab bar. A UIKit bridge preserves the native Liquid Glass appearance but intercepts direct tab presses before UIKit's selection-platter animation, synchronizes the SwiftUI selection in a disabled-animation transaction, and then applies the native selection without animation. The center item becomes an icon-only Start while Today is idle and otherwise remains Today navigation. Today keeps a stable map instance extending behind the transparent navigation bar to the screen top and ending at the fixed two-row dock. The shell owns one assistant launcher with identical bottom-leading placement across all three tabs. Idle Today’s top-right overflow menu owns Photo and Find Route; a captured photo replaces the ellipsis label with a circular thumbnail carrying a small ellipsis badge. Selected routes propagate out of the retained recorder so the shell map fits and highlights the route while the launch surface presents a compact name/distance card with Change and Remove. Planned reuses the existing Today card and Up Next implementation as a standalone bottom-aligned peer stack without intercepting map touches outside the cards; target-based modes show their compact goal information in that region, while Freestyle leaves the map unobstructed. Dock controls visually contain only an icon and localized title while retaining accessibility values. Duplicate Quick Start and in-card Start buttons are suppressed while the dock is present. Me previews accepted connections through the shared social-profile link: tapping an avatar opens that runner's profile, while the ellipsis opens Connections for management and discovery. Beneath weekly progress, Me shows recent local-first recognition and links to earned moments grouped by family; locked badges remain hidden. Tapping the Me profile header opens one consolidated editor for photo, public profile, contact information, private health/training details, and a separate companion-memory entry. The production Settings route is limited to account controls, companion preferences, themes, units, health, gear, integrations, safety, feedback, app version, and DEBUG-only onboarding replay.
- `Features/Planning/TrainingPlanViews.swift`: reusable plan picker, recommendation detail, active-plan detail, loading states, and progress UI. Today keeps one-day `Change workout` adaptation separate from its compact Plans, Workouts, and Routes navigation tiles. Each tile shows the active selection when available; plan management remains inside the plan detail, and replacing an active plan requires explicit confirmation.
- `Features/Planning/StandaloneWorkoutLibrary.swift`: server-backed plan-independent workout catalog and picker. It fetches the authenticated catalog from `/v1/planning/standalone-workouts`, caches the last good response for offline use, and launches the selected server-defined intent through the shared recording and live-guidance flow without creating or changing a multi-week plan.
- `Domains/Social/SocialHomeView.swift`: production Social home plus Connections, comments, notifications, Groups, sharing, and group-run detail UI. It supports connection lifecycle, activity sharing, reversible Cheers, comments, reports, blocks/unblocks, an in-app inbox, Group membership, RSVP, targeted invitations, and invitation acceptance. Social mutations use the app-wide optimistic-interaction rule: update visible state immediately, then roll back and show a temporary error toast when the API fails.
- `DesignSystem/OutboundDesignSystem.swift`: target design tokens, the eight adaptive app-theme palettes, reactive theme environment, and reusable card, primary-button, AI-explanation, and workout-phase summary components. See `docs/themes.md` before adding or applying theme styling. New simplified-product features should extend these components instead of adding styles to legacy monolithic screens.
- `Domains/Athlete/PersonalizationContracts.swift`: versioned Codable contracts for calibration workouts, runner insights with confidence, readiness, post-run feedback, and explainable plan adjustments. Today consumes the cached backend snapshot and retains a typed preview fallback for offline first render.
- `Domains/Athlete/PersonalizationStore.swift`: cached API-backed personalization state with idempotent offline queues for readiness and post-run feedback, plus adjustment decisions.
- `Features/Onboarding/SimplifiedOnboardingFlow.swift`: five-step target intake for goal, baseline, realistic week, optional private training details, and a combined editable-understanding/calibration review. Training details accept manual entry, Apple Health, or one-tap skip. Completing the flow persists runner facts and starts the recommended plan.
- `Integrations/HealthKit/HealthWorkoutImportView.swift`: shared review-and-confirm sheet for new Apple Health workouts. It is presented after foreground scans and from Me, then saves selected workouts with UUID-backed source attribution for deduplication.
- `Features/Personalization/PersonalizationViews.swift`: calibration progress and pre-run readiness surfaces for the first personalized-companion vertical slice.
- `Activity/PostRunSummaryView.swift`: places an optional one-tap effort reflection directly after the finish message on every workout. The finish page also lets runners take, delete, and drag-reorder photos before saving. Continuation capacity appears only after `Easy`. Save is always available, never waits for the network, and feedback is queued when offline.
- `App/OnboardingStore.swift` and `App/OnboardingFlowView.swift`: local-first new-user onboarding. The store tracks account-scoped completion/profile state in `UserDefaults`; the view gathers free-text goal, baseline, and realistic-week intake, exact body basics for calorie estimates, and a guide-review summary, then can launch the personalized first session through `MainTabView`.
- `OutboundLiveActivityExtension/`: WidgetKit extension that renders the active-session Live Activity for the lock screen and Dynamic Island.

## Recording

- `Activity/RecordView.swift`: owns the Today-embedded map launch dock, countdown, and recording flow. Planned, Freestyle, Distance, Time, and Calories remain peer modes; a flat second row retains scrolling Music, Live Track, Shoes, the current Indoor/Outdoor choice, and Voice Guide settings. Voice Guide defaults on for new installs while preserving an existing runner's saved choice. The retained view handles shell Photo requests and reports captured-photo state so the shell action becomes a checked thumbnail after capture. The contextual center Start control begins the countdown immediately with no intermediate setup route. The same retained view then runs the live camera/map experience, recording recovery, guidance, live sharing, pause/resume/finish, and reflection-first Save/Discard flow. Countdown retains a cancel action, but active and paused recording are non-dismissible and keep the tab bar hidden until Finish hands off to Save or Discard; the assistant remains available as an overlay.
- Music discovery: after Apple Music status refreshes, disconnected, denied, or playback-ineligible users see a once-per-view popover anchored to the fixed Music control. Music started for an interrupted workout keeps a lightweight local recovery intent and provider item metadata; after relaunch restores the workout as paused, tapping Resume resumes an existing Apple Music queue or rebuilds the selected queue before playback continues.
- `Activity/ActivityGoal.swift`: per-session goal model for freestyle, distance, time, and calorie starts, plus helpers that convert selected goals into `SessionIntent` values.
- `Core/ActivityRecorder.swift`: main activity state machine. Tracks elapsed time, distance, current pace, heart-rate placeholder, and `liveSnapshot`. Elapsed time is derived from active wall-clock segments rather than only a foreground timer, and location updates also refresh the live snapshot so guidance continues while the app is backgrounded during a run. Supports pause/resume by stopping both the UI timer and GPS updates without discarding the current track. `finish()` returns `ActivitySummary` with track points.
- `Core/ActiveSessionJournal.swift`: writes compact atomic metadata during recording and at pause/resume boundaries, appends only newly accepted track locations to a chunked trail journal, and persists setup/live photos plus their local metadata in a separate session-photo directory. Route Guidance stores its immutable prepared-route snapshot once in a separate atomic file while metadata checkpoints carry compact engine progress. If the process is interrupted, `ActivityRecorder` restores elapsed time, activity type, actual trail, exact route/direction, route progress, and captured photos as a paused session; `MainTabView` immediately presents that recovered paused session in the non-dismissible live surface.
- `Core/ConnectivityStore.swift`: monitors reachability and drives the shared app-level offline, reconnecting, synced, and sync-attention banner. Reconnection triggers the existing deferred activity queue immediately. Starting and recording never wait for this signal; the full-screen recording UI retains its compact in-context status treatment.
- `Core/SessionLiveActivityManager.swift`: ActivityKit bridge that starts, updates, and ends the active session Live Activity using recorder snapshots. A stable session start time lets a relaunched app adopt the ActivityKit-owned card and immediately dismiss duplicates instead of requesting another card. Finish and discard also dismiss any surviving app-owned session activity.
- `Shared/OutboundLiveActivityAttributes.swift`: shared ActivityKit attributes/content-state model compiled into both the app target and the widget extension.
- `Core/LocationManager.swift`: CoreLocation/CoreMotion workout wrapper. It warms a fresh high-quality fix during countdown, requests temporary precise location for outdoor workout accuracy when iOS has granted only approximate access, preserves chronological background batches, and publishes the latest usable raw fix separately from the filtered recorded trail. Distance uses sport-aware uncertainty, speed accuracy, stationary suppression, adaptive constant-velocity smoothing, explicit pause/resume segments, and pedometer assistance across short GPS gaps. Manual pauses stop acquisition; auto-pauses retain a private probe buffer and promote only confirmed resumed movement. Recovery restores segment boundaries so it never adds a straight-line pause or relaunch bridge.
- `Core/LocationTrackProcessor.swift`: shared streaming filter plus finish-time symmetric cleanup. Finish recomputes canonical distance/elevation per segment and conditionally projects a selected-route recording onto the prepared polyline only when point accuracy, course, proximity, continuity, and overall match coverage are high enough; ordinary freestyle and off-route movement remain unsnapped.
- `Core/ElevationGainCalculator.swift`: rejects vertically inaccurate or implausible samples, applies a rolling median, and uses climb/descent hysteresis to report cumulative ascent instead of only maximum-minus-minimum altitude.
- `Core/ActiveSessionSnapshot.swift`: lightweight real-time snapshot passed to the guide.
- `Core/SessionFormatting.swift`: shared locale-aware formatting helpers for displayed and spoken distance, elevation, pace, temperature, and elapsed time. Distance and temperature have independent device-derived defaults and explicit user selections.
- `Core/UserPreferencesSyncStore.swift`: local-first, account-backed preference coordinator. On sign-in it restores the server snapshot, uploads the local snapshot for accounts without one, observes only durable preference fields, and debounces later changes. Transient failures remain retryable, while an unchanged snapshot rejected with HTTP 400 waits for a real preference change instead of entering a request loop. The snapshot covers units, voice/live-guidance selection and enablement, appearance/theme, shoes/default shoe, durable music choices, and preferred activity setup controls; health-cycle details and transient provider/playback state stay out of it.

## Camera

- `Camera/CameraController.swift`: AVFoundation capture session, camera authorization, session queue, retained photo-capture delegates, still-photo capture, and the persisted front/back camera preference (front on first use).
- `Camera/CameraPreviewLayer.swift`: SwiftUI wrapper for `AVCaptureVideoPreviewLayer`.
- `Camera/CameraHUDView.swift`: full-screen camera plus a Strava-style bottom state card and a right-edge control rail during an active session. The card uses adaptive system surfaces and the selected app theme for status, controls, border, and glow. Structured workouts show a readable full-width step row with progress, phase name, and remaining time. While recording, the card shows live stats, the latest guide message, music state, and Pause; while paused, it expands into Resume and Finish. Finish stays disabled while a high-resolution photo capture is pending so the capture delegate and journal write complete before the live surface is dismissed. When local live sharing is active, the rail shows a stop-sharing control. Captured photos are returned to `RecordView` with `PhotoMetadata`, including whether the shot was taken while active or paused.

## Local Persistence

- `Core/LocalActivityStore.swift`: saves finished activities under Application Support at `Outbound/Activities`. Manifest reads/writes, upload-size photo compression, downloaded-photo persistence, deletion, replacement/upsert, and route export are serialized by `ActivityPersistence` off the main actor; `ActivityStore` returns to the main actor only to publish UI state.
- `Activity/ActivityStore.swift`: keeps history local-first, then performs authenticated two-way synchronization after sign-in and whenever the app becomes active. It pulls paginated server snapshots and deletion tombstones, restores missing activities and private photos, upgrades legacy uploads, uploads new/edited local records and unsynced photos, and sends server deletes before removing local data. `ActivityHistoryView` presents this complete local history in 20-row pages, so pagination never makes progress totals or background synchronization incomplete. Activity snapshots omit photo bytes; photo metadata lives in the backend and JPEG bytes use the existing private Firebase Storage/GCS bucket.
- `activities.json`: manifest containing `SavedActivity` entries with a canonical activity type (`running`, `cycling`, `hiking`, `walking`, or `swimming`), source attribution, optional gear/indoor/manual-edit/cadence/heart-rate-zone metadata, optional per-session goal metadata, post-activity finish reflections, compact canonical route data for saved activities, and saved photo metadata. Older manifests without a type load as `running`; raw `trackPoints` and legacy guide nudges also retain backward-compatible decoding.
- Per-activity photo files are stored locally as JPEGs under `<activity-id>/photos/`; remote copies use `activity-photos/<user-id>/<server-activity-id>/<client-photo-id>.jpg` and are served only through authenticated API routes.
- Saved route points retain pause/resume segment starts. Live, post-run, activity-detail, share-card, GPX, and GeoJSON rendering/export avoid drawing teleport lines across those gaps; segmented GeoJSON uses `MultiLineString`.
- `Core/LocalActivityStore.swift`: also contains the canonical route model plus on-demand route export helpers for `GPX` and `GeoJSON`, so the app stores compact route data and only materializes share files when needed.
- `Routes/CommunityRouteStore.swift` and `Routes/CommunityRouteViews.swift`: own lightweight server-backed route summaries, on-demand detail geometry, an LRU offline cache capped by route and canonical-point counts, nearby/search/My Routes surfaces, owner-only publication, bookmarks, aggregate-capped GPX/GeoJSON preparation, direction selection, and route launch into the shared recorder.
- `Routes/RouteGuidanceEngine.swift`: reusable deterministic exact-polyline engine. It preprocesses an error-bounded, length-retaining working geometry with a constant-pass pathological-input cap and spatial lookup once, rejects geometry that cannot safely fit that cap, reverses the same validated line for reverse guidance, requires acquisition near the directed start, then produces progress, remaining distance, deviation/rejoin, wrong-way, and terminal arrival state without full-route scans per GPS fix or maneuver/rerouting claims. See `docs/route-saving-sharing.md` for the full contract.

## Progress

- `Progress/ProgressStatsEngine.swift`: pure local stats engine shared with the Swift Package target. It derives current-week totals, four-week buckets, best efforts, PR history, race predictions, one momentum note, and a lightweight guide note from `ProgressActivity` inputs without depending on SwiftUI or `SavedActivity`.
- `Progress/ProgressView.swift`: Strava-style Progress surface opened from Me. It adapts saved activities into `ProgressActivity`, computes route-window best efforts from canonical route points, and organizes weekly summary/recent stats, trends, records, and gear mileage into Now, Trends, Records, and Gear tabs.
- `Tests/OutboundSessionAnalysisTests/ProgressStatsEngineTests.swift`: focused Swift Package coverage for current-week totals, four-week buckets, route-window best efforts, fallback efforts, longest run, best weekly distance, PR history, race predictions, and momentum notes.

## Companion And Session Analysis

- `Guide/GuideTemplate.swift`: defines stable Plainstride coach-persona and acoustic voice-profile IDs. Persona, voice, coaching contract, tone, and stat frequency remain separate product choices; no provider voice ID is stored on-device.
- `Guide/GuideCatalogStore.swift`: persists the selected persona/voice and refreshes the authenticated server catalog. If a saved combination disappears, it selects that persona's server-approved default voice.
- `Guide/GuideSelectionView.swift`: shows only compatible server-approved personas and voice profiles. Preview controls play the selected pack's reviewed `voice.preview` asset and report temporary failures with a toast.
- `Core/ActiveSessionSnapshot.swift`: defines typed per-session and per-step coaching targets. Workout phases opt into personalized or absolute pace bands explicitly; localized step labels are never parsed to invent coaching meaning.
- `Guide/LiveGuidanceModels.swift`: defines the coaching contracts, opt-in two- and three-minute challenges, semantic moment types, cue outcomes, post-run feedback, session report, and the stateful director. The director detects personalized above/below-target pace, early overpacing, instability, target lock, drift, measured rhythm recovery, recovery run too hard, reliable climbs/crests, finish opportunities, and existing challenge moments. Terrain suppresses flat-ground pace advice. Responsive mode can suppress repeatedly unhelpful moment types using locally persisted aggregate evidence.
- `Guide/VirtualGuide.swift`: keeps moment detection, plan-phrase selection, cooldowns, route priority, outcome evaluation, progress scheduling, and stale-cue rejection on-device. Route announcements use generic reviewed clips rather than arbitrary street/place names. It uses exact-text system speech only after the 1.5 second cloud-audio deadline or when no reviewed/planned audio exists.
- `Guide/GuideAudioPlayer.swift`: plays streaming 24 kHz mono PCM through `AVAudioEngine`, planned/fixed WAVs through `AVAudioPlayer`, and exact-text last-resort speech through `AVSpeechSynthesizer`, with spoken-audio ducking, interruption, and priority cancellation. At session start it resolves and pins a same-language system voice matching the selected female/male product presentation; if no matching voice exists, it declines on-device speech instead of switching presentation mid-session.
- `Guide/GuideAudioPackStore.swift`: verifies ES256-signed approved manifests against the expected catalog version and verifies SHA-256 asset checksums, retains the last known-good cache, supports a reviewed bundled `LiveCoachAudio` fallback pack, and selects assets by compatible product persona, locale, product voice, semantic cue, and script style.
- `Guide/SessionAnalysisProvider.swift` and `Guide/ServerLiveCoachProvider.swift`: define the provider-neutral client boundary. Requests contain a semantic moment, a server-issued planned phrase ID, and bounded live state; responses contain provider-neutral classifications plus streaming PCM, planned/fixed WAV, or an exact-text fallback. Dynamic access is limited by eligible workout sessions, never by cue count; local cooldowns and server request-rate controls govern cadence without ending guidance mid-workout.
- `docs/live-coaching-moments.md`: current canonical moment definitions, thresholds, target population rules, confidence/safety gates, audio mappings, and future wearable/form taxonomy.
- `Guide/LiveCoachSessionController.swift`: sends the client workout/route summary and weather environment, creates one authenticated server session, receives the phase-aware Gemini plan, rotates eligible phrases, applies the plan's progress cadence, prewarms up to eight likely phrases, pins mode/access, refreshes the reviewed pack, and ends best-effort.
- `Guide/GuidePlannedAudioCache.swift`: stores generated-plan WAVs under a content-addressed plan/voice/phrase key and purges entries after 24 hours.
- `Guide/GuideProfile.swift`: athlete/guide profile model used to contextualize analysis.
- `Guide/GuideStore.swift`: loads/syncs the authenticated user's guide profile through `APIClient`; the backend derives identity from the existing Plainstride access-token boundary rather than accepting a user ID in the route.

## Motivation

- `App/OutboundApp.swift`: now also defines `DailyCheckInStore`, which persists one local readiness selection per day in `UserDefaults`.
- `Goals/GoalModels.swift`, `Goals/GoalProgressEngine.swift`, and `Goals/GoalStore.swift`: local-first weekly focus models, progress computation from saved activities, and persisted guide conversation state.
- `Goals/GoalConversationCard.swift`: motivation-card UI for conversational goal setup, active-focus progress, and lightweight adjustment.
- `App/OutboundApp.swift`: now also defines training plan response models and `TrainingPlanStore`, which fetches server-owned plan state through `APIClient`, caches the last active plan/week/today payload for offline rendering, and falls back to local deterministic rules when the API is unavailable.
- `App/TrainingPlanLibrary.swift`: offline fallback structured plan library. It stores `TrainingPlanTemplate`, `TrainingPlanWeek`, `TrainingPlanWorkout`, and `TrainingPlanWorkoutStep` content, including Outbound-authored consistency, comeback, 5K, 10K, 10 mile, half marathon, marathon, and base-building plans. Retained MIT imports are compatibility/fallback content, while authenticated recommendation and Today flows use the backend-curated catalog as the source of truth.
- `App/MainTabView.swift`: retains the session models plus the motivation phase and post-run reflection engine used across planning and recording. The retired `MotivationDashboardView` and its shell controls have been deleted; the production Today UI lives only in `Features/Simplified/SimplifiedAppShell.swift`, with no legacy-shell launch flag.
- `docs/new-user-onboarding.md`: product and implementation notes for first-win onboarding and the DEBUG-only Settings replay trigger.
- `docs/goals-progress.md`: the product and implementation spec for local-first focus and goal tracking. The V1 implementation now uses `GoalStore`, progress chips in Me's motivation surface, and goal-aware post-run reflection notes.

## Integrations

- `Integrations/HealthKit/HealthKitService.swift`: lightweight `HealthKit` wrapper that defines the initial workout import/write-back permission set, exposes authorization snapshot state, and safely reports unavailable environments.
- `Integrations/HealthKit/HealthAuthorizationStore.swift`: UI-facing observable stores for refreshing HealthKit permission state, requesting Apple Health access from the Me tab, and previewing recent imported workouts with a normalized `ImportedWorkout` model.
- `Integrations/Weather/SituationalWeatherStore.swift`: WeatherKit integration for Today. Opening Today automatically requests permission when needed, then performs a one-shot reduced-accuracy location lookup, caches a normalized 30-minute snapshot, derives bounded running guidance and a near-term outdoor window, and exposes an expiring situational signal to the companion without sending coordinates. Weather guidance can recommend a small adjustment but does not mutate the plan.
- `Features/Simplified/SimplifiedAppShell.swift`: Today renders the local-condition result, loading state, or actionable error directly inside the workout card. The detail sheet explains any weather guidance, forecast privacy, and Apple Weather attribution; unavailable weather never blocks the workout. A sparkles control on the activity card opens contextual guidance and conversational customization; duration and effort requests update the visible card and the activity launched from it immediately.

## Safety And Runner Utilities

- `Safety/LiveShareStore.swift`: network-backed live-share state. It can arm the next activity, create a server private-link session with optional trusted-contact delivery targets, prepare Share Sheet copy, send throttled live location updates, expose stale/unavailable status, and end sharing from finish/discard or the live HUD.
- `Safety/SafetyContactStore.swift`: local-first trusted-contact list stored in `UserDefaults`, including default recipient, SMS/push channel labels, and enabled state. Server delivery is currently stubbed while the app still opens the system Share Sheet.
- `Gear/GearStore.swift`: local-first running shoe inventory stored in `UserDefaults`, with default-shoe selection, retirement, and mileage summaries derived from saved activities.
- `RecordView`: has a pre-start `Share live run` toggle, selected/default trusted-recipient status, and a treadmill/indoor toggle; save attaches default shoe, source attribution, indoor metadata, and estimated HR-zone summary when HR exists.
- `ActivityDetailView`: shows source, edited/manual, shoe, indoor, cadence, and HR-zone metadata and includes an edit sheet for title, date, distance, duration, and shoe corrections.
- `docs/runner-utilities.md`: runner-utility roadmap for remaining import/export breadth, fuller HR/cadence ingestion, and device/source polish.
